How to remove duplicate files on Mac, safely

Updated: October 29, 2026 · 7 min read

Quick answer

Duplicates pile up from downloading the same file twice, exporting again, and copying folders between projects. For photos, use Photos › Utilities › Duplicates and merge. For other files, compare by content, not by name, always keep one copy, and before deleting a copy inside a project, check that no script points to that exact path. Move duplicates to the Trash rather than deleting them outright.

Why duplicates pile up

  • The same file downloaded twice: report.pdf, report (1).pdf, report (2).pdf.
  • Video and design exports saved again after a small change.
  • Folders copied between projects "just to be safe".
  • Photos imported from a phone and also saved from a chat app.

Photos: use the built-in Duplicates

If your pictures live in the Photos app, use Apple's own tool:

  1. Open Photos and click Duplicates under Utilities in the sidebar.
  2. Select the duplicates to merge (Command-A selects all).
  3. Click Merge and confirm. One original stays in your library; the rest go to Recently Deleted, where you can recover them for 30 days.

Never delete files inside the Photos library package in Finder. Always work from the Photos app.

Other files: find them by hand

  • In Finder, search your Downloads for (1) and copy to catch the obvious ones.
  • Sort folders by Size: identical files often sit next to each other with the same size.
  • Before deleting, open both copies. Same name and size is a strong hint, not proof that two files are identical.

This works for a few files. For a whole drive, a tool that compares file contents is faster and more reliable.

The real risk: breaking a project

Most duplicate finders only ask "are these two files the same?". For people who write scripts, automations or AI skills, a second question matters: does something point to this exact copy?

A Python script that reads data/prices.csv, a shell script that copies assets/logo.png, a skill file that names a template: delete that copy and the script breaks, even though an identical file exists somewhere else. The file wasn't junk. Its location was the point.

Four rules for a safe clean-up

  1. Match by content. Same name does not mean same file, and the same file can have different names.
  2. Always keep one copy, preferably the one outside Downloads, Desktop and temp folders.
  3. Check your projects before removing a copy that lives inside one.
  4. Use the Trash, not permanent delete, so a mistake costs you a drag back, not a lost file.

FAQ

Is it safe to delete duplicate files on Mac?

Yes, if you keep one copy, match files by content rather than name, and move them to the Trash so you can undo. Check first that no script or project points to the copy you remove.

Does macOS have a duplicate file finder?

For photos and videos, yes: Photos › Utilities › Duplicates lets you merge them. For other files, macOS has no built-in duplicate finder.

Can two files with the same name be different?

Yes. Name and size are only hints. Comparing the content (a checksum) is the reliable way to know two files are identical.

Which copy should I keep?

Usually the one inside an organised folder rather than Downloads or Desktop. If a script or project uses one copy, keep that one.

How does Tidymint protect projects?
